**Ranked list of task beads to work**

1. **`sase-1db` — Verify private attachment destinations before uploading.** Ready; **medium**. Highest priority because this can turn an explicit privacy expectation into irreversible publication. Current code still checks a sidecar's requested visibility only in the `not_found` creation case (`src/sase/sdd/_sidecar_init.py:132–172`), while `attachments/upload/discovery.py:155` labels a destination from the requested audience. The prerequisite `sase-1d5` is closed; its lander explicitly says only the doctor finding was delivered, leaving existing-remote preflight, upload enforcement, and labeling outstanding.

   **Recommended solution:** enforce a verified-private destination at preflight and at the private upload boundary, keyed to the actual remote identity. Reuse the existing visibility machinery and provider metadata, but distinguish “not anonymously readable” from affirmative privacy verification: a 404 or network failure is not sufficient proof. Refuse a public destination; retain bytes locally with a clear pending/error outcome when privacy cannot be established. Make labels reflect verified state, and revalidate when remote identity changes or evidence expires. Share the policy through the Rust domain boundary if it is used across frontends; keep network I/O in the adapter. Do not alter the scanner rules being changed by `sase-1r8`.

   **Done when:** tests prove zero push calls for public and unverified destinations, successful private upload for a confirmed private remote, safe handling of visibility/remote changes, and accurate labels. Include an existing-public-remote fixture, not just new-repository creation. **Confidence: high for the open code path; no claim of an observed leak.** Source: audited `bead:sase-1db` and `bead:sase-1d5`; current preflight/discovery/store source.

2. **`sase-1r4` — Recognize update-induced signature errors and settle failed staged adoptions honestly.** Ready; **large**. The bead documents November 3 effects across multiple runs: 13 files of Bob work left uncommitted, a monitor stuck staged for hours, and release work requiring manual recovery. My direct classifier probe still returned false for the unexpected-keyword `TypeError`; `_SKEW_TYPE_NAMES` and `_SKEW_MESSAGE_PATTERNS` in `src/sase/axe/runner_failure_facts.py:32–59` omit that case.

   **Recommended solution:** recognize narrow signature-change patterns using structured exception facts and code-identity change evidence. Do not label every `TypeError` update skew. Extend the boot-safe explanation path, and make failed staged adoption persist an accurate failed/held outcome instead of leaving a pid-less staged monitor looking runnable. Preserve custody and the accepted declaration so existing recovery can finish it. Keep this task out of generic recovery launch, workspace transfer, and restart policy owned by `sase-1qz`; immutable releases and general resume-in-place remain separate beads. The active Codex adapter fix does not cover this failure class.

   **Done when:** a revision-A runner/revision-B signature fixture gets an honest skew diagnosis and a non-zombie adoption outcome; an ordinary same-revision application `TypeError` remains an application failure; no failure path reruns completed provider work or drops dirty repository obligations. **Confidence: high for classification, incident-backed for adoption consequences.** Source: `bead:sase-1r4`; `runner_failure_facts.py`, `source_skew.py`, `run_agent_exec_staged_adopters.py`.

3. **`sase-1qe` — Remove quadratic per-test home allocation.** Ready; **small**. This is the strongest effort-adjusted throughput improvement. Every test enters the autouse fixture in `tests/_conftest_environment.py:276`, which still calls `tmp_path_factory.mktemp("home")`. The bead reports a worker with 27,816 basetemp entries during a check lasting over two hours. My smaller controlled probe independently confirms rising per-allocation cost, roughly 40 times higher at 10,000 entries than at 100.

   **Recommended solution:** allocate one per-worker/session parent, then create unique per-test homes with `tempfile.mkdtemp(dir=parent)` or an owned monotonic allocator. Keep each home outside the individual test's `tmp_path` and preserve isolation, teardown ordering, and leak-guard conventions. Do not reuse the same mutable home between tests.

   **Done when:** uniqueness/isolation tests pass across workers, tests that enumerate their own `tmp_path` stay unchanged, and a 1k/10k/30k allocation benchmark has approximately constant per-allocation cost. Measure an equivalent check lane before/after without claiming the microbenchmark ratio as suite speedup. Sequence with rank 9 because both touch the fixture file. **Confidence: high.** Source: `bead:sase-1qe`, current fixture, this turn's allocation probe. The active release epic's completed CI fixes have not removed this call.

4. **`sase-1pw` — Make pytest worker-token admission starvation-free.** Ready; **medium**. This wastes entire verification attempts under exactly the multi-agent load now present. The bead records a four-token waiter timing out after **45 minutes**, while younger holders received grants. `tests/_suite_gate_lease.py:121–233` still polls without an arrival ticket and greedily takes up to the request ceiling; there is no mechanism reserving eventual progress for an older request.

   **Recommended solution:** add durable arrival ordering and dead-waiter reclamation under the pool lock. Guarantee the oldest feasible request its minimum grant before younger requests expand opportunistically. If allowing backfill, make it bounded and prevent it from indefinitely consuming the capacity needed by the old request. Keep the nonblocking `try_acquire` contract, host capacity limits, and crash-safe token ownership. This is test infrastructure, separate from runtime agent admission and the active publication drain scheduler.

   **Done when:** a deterministic repeated-arrivals test proves the older four-token request eventually obtains its grant; mixed floor/ceiling, cancellation, dead waiters, capacity changes, and opportunistic callers stay correct. Do not “fix” this by extending the 45-minute timeout. **Confidence: high, with current mechanism and recorded rotating-holder evidence.** Source: `bead:sase-1pw`; `tests/_suite_gate_lease.py` and its pool helpers.

5. **`sase-1kp` — Separate the bead mutation lock from the Python SQLite mirror's file identity.** Ready; **large**. Current Rust still defines `BEAD_MUTATION_LOCK_FILENAME = "beads.db"`; Python's `BeadProjectStoreMixin._conn` caches a SQLite connection to that same pathname. My two-process probe confirms that closing another descriptor for a file releases the process's POSIX record lock on that file. This creates a credible mirror-integrity/crash hazard; the bead scopes it to CLI paths rather than the already-fixed TUI ownership issue.

   **Recommended solution:** inventory remaining Python mirror consumers and preferably retire the mirror in favor of Rust-owned queries. If compatibility requires a mirror, move that disposable SQLite database to a distinct inode/path while retaining the established Rust mutation-lock protocol. Update cache rebuilding, ignores, staging exclusions, and cleanup together. Simply renaming the Rust lock without a mixed-version transition can allow old and new writers to mutate concurrently. Dual-locking while continuing to open/close the SQLite inode does not remove the descriptor-close hazard.

   **Done when:** a multiprocess regression exercises a Python mirror connection across Rust mutations, verifies lock exclusion and database integrity, and covers old/new reader-writer coexistence and event-log replay. Do not describe the mirror risk as proven canonical event loss: I did not reproduce corruption. **Confidence: high for shared-file design and lock mechanism, medium for production frequency.** Source: `bead:sase-1kp`; core `bead/mutation/store.rs:46,511–590`; sase `bead/_project_store.py:32–42`.

6. **`sase-1ce` — Preserve edited prompts when the external editor fails.** Ready; **small**. The defect is direct user-data loss and still obvious in current code. In `src/sase/ace/tui/actions/agent_workflow/_editor.py`, nonzero editor exit returns `None`, then `finally` unlinks the temporary prompt file. The workflow-YAML editor repeats the pattern. A user can write a long draft and lose its saved file on `:cq`, editor crash, or termination.

   **Recommended solution:** compare recoverable file bytes with the initial content on nonzero exit or launch/read failure. Preserve changed content in a durable recovery location or successfully stash it before unlinking; tell the user where it is. Do not interpret recovery as permission to submit the prompt. Delete on success or unchanged cancellation, and preserve exact content rather than stripping recovery text. Ensure generic managed-temp cleanup does not immediately remove the saved recovery file.

   **Done when:** fake-editor tests cover changed/nonchanged nonzero exit, exception, successful save, and workflow YAML; changed bytes remain recoverable and no accidental prompt launch occurs. This uses the existing editor/preservation boundary, not the recovery panel under active `sase-1qz`. **Confidence: high.** Source: `bead:sase-1ce`; current `_editor.py` prompt and YAML editor functions.

7. **`sase-1cg` — Cancel TUI restart when its draft stash fails.** Ready; **small**. Another deterministic loss path, distinct from editor failure. The current location has moved from the bead's older `axe.py` reference to `src/sase/ace/tui/actions/axe_quit.py:211`. It sets the restart action, stops the watchdog, converts stash failure to false, marks `_quit_draft_stash_attempted = True`, and exits. `_prompt_bar_stash.py:61` discards the distinction between “no draft” and “save failed.” The normal quit guard consequently cannot protect the draft.

   **Recommended solution:** preserve the existing tri-state stash result. Attempt the stash before setting exit action or stopping the watchdog. On failure, leave the draft and TUI intact, keep the quit guard available, and show the failure; proceed only on success or no draft. Share the established quit-preservation behavior rather than creating another storage path. This is TUI process restart safety, not an agent-restart redesign.

   **Done when:** injected storage failure prevents both restart variants, leaves the watchdog and UI usable, and retains the draft. Successful restart saves exactly once and no-draft restart still works. Coordinate integration with rank 6 and leave the hijack prompt-pane wiring alone. **Confidence: high.** Source: `bead:sase-1cg`; `axe_quit.py`, `_prompt_bar_stash.py`, and `actions/lifecycle.py`.

8. **`sase-1mb` — Drain Git batch output while writing batch input.** Ready; **medium**. Large history queries can deadlock beyond their advertised timeout: core `file_history/blobs.rs::read_blobs` writes all OIDs before reading stdout; `memory_history/causes.rs::batched_diff_tree` does the same for commit IDs. Those orderings remain in the opened core checkout. A deadline checked before a blocking write does not interrupt that write. The bead contains an earlier isolated pipe-pressure reproduction of both protocols.

   **Recommended solution:** migrate both callers to the existing concurrent `run_git_unchecked_with_stdin` runner (or its bounded streaming seam if required for blobs). Preserve missing/oversized blob semantics, byte framing, output limits, environment hardening, timeout enforcement, and child cleanup. Treat truncation explicitly; do not make concurrent draining an excuse to accumulate unlimited output.

   **Done when:** input and output both exceeding pipe capacity complete or time out within the bound; malformed/missing/oversized objects preserve behavior; output cap and cancellation leave no child process. This changes two known history callers, not the active core release/CI workflow. **Confidence: high from code plus recorded protocol reproduction; no fresh deadlock test in this turn.** Source: `bead:sase-1mb`; core `file_history/blobs.rs`, `memory_history/causes.rs`, `file_history/runner.rs`.

9. **`sase-1q3` — Isolate tests from ambient `SASE_MODEL_OVERRIDE`.** Ready; **small**. This is a reproducible environment defect masquerading as test regressions. The bead records **7 failures / 44 passes** with the override and **51 passes** on the unchanged tree without it. Current `_clear_agent_env_vars` in `tests/_conftest_environment.py:437` scrubs alias overrides but still omits `SASE_MODEL_OVERRIDE`. It can alter both model choice and provenance trailers in checks launched from agent environments.

   **Recommended solution:** remove the ambient variable in the autouse isolation boundary, retaining explicit test-local overrides and proper restoration. Cover the process boundary, not merely a test that calls the scrub function directly. Audit the related model override names only enough to avoid a second known equivalent leak; do not broaden this into a test-framework rewrite.

   **Done when:** a subprocess pytest run with an inherited override and a clean control produce the same expected results, while a test explicitly setting an override still exercises it. Land after rank 3 or have one worker handle both beads sequentially to avoid editing the same fixture concurrently. **Confidence: high; current omission plus unchanged-tree control evidence.** Source: `bead:sase-1q3` and its October 30 control note; current environment fixture.

The worker may explicitly defer bead-sync adoption with evidence if cadence already provides adequate recovery. **Confidence: high for the missing integration, impact supported by the task's incident evidence.** Source: `bead:sase-1r7`; `src/sase/sdd/_sidecar_git.py`, `axe/runner_workspace_sidecar.py`, `vcs_provider/plugins/_git_commit_dispatch.py`, `bead/_sync_worker_run.py`; active publication plan's explicit exclusion.
