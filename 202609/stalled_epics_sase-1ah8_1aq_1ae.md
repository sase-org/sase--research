# Why three SASE epics remain open

Snapshot: 2026-09-26 17:14 EDT. Statuses and dependencies below come from audited `sase bead read` results; live owner state was checked with `sase agent list` and `sase agent show`. These are unfinished acceptance chains, not three instances of the same defect.

## `sase-1ah.8` — E4 receipt reporting

All three phases remain open. [Phase `.1`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-1ah/sase-1ah.8.1.md) records the Rust report and passing focused tests, but its final `just check` monitor failed: 11 Symvision findings were triaged KNOWN and `init memory --check` found a four-line README regeneration drift under an UNKNOWN validation failure. Its worker is done and the bead has not closed. [Phase `.2`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-1ah/sase-1ah.8.2.md) waits for `.1`, then must replace the Python implementation, advance the core pin, and require a published receipt-capable wheel for fresh installs. [Phase `.3`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-1ah/sase-1ah.8.3.md) waits for `.2` and still owes live Athena pass/no-new/drift completion proof and the dated owner check. Next: resolve or explicitly triage the failed check and finish `.1`; then release/adopt the wheel and run live acceptance. [Approved plan](https://github.com/sase-org/sase--plans/blob/main/202609/e4_landing_remainder.md).

## `sase-1aq` — hold, dispatch, and parity closeout

Phases `.1`–`.4` are closed, including hold landing, runtime adoption, and a live Apollo snapshot. The immediate gate is [`.5`'s unified Athena–Apollo matrix](https://github.com/sase-org/sase--beads/blob/main/pages/sase-1aq/sase-1aq.5.md): its helper launch reported an *uncertain* Apollo outcome (`unsupported fleet launch store schema_version`), and no current `.5` worker appeared in the live agent list. The original [snapshot bead `.7.5`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-xe/sase-xe.16.11.7.14.6.7.5.md) has supporting evidence but still awaits normal close; the subsequent [unified-proof bead `.7.6`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-xe/sase-xe.16.11.7.14.6.7.6.md) remains open. Therefore `.6` cannot land the `sase-xe` ancestors; `.7` must then close [production/live Agents parity](https://github.com/sase-org/sase--beads/blob/main/pages/sase-133/sase-133.5.4.md), whose last recorded live screenshots failed parity and whose same-build acceptance is still open. `.8` memory publication and `.9` final audit wait behind them. Next: reconcile the uncertain launch without replaying its key, close `.7.5` on its evidence, complete `.7.6` and `.5`'s live matrix, then land dispatch and parity in order. [Approved plan](https://github.com/sase-org/sase--plans/blob/main/202609/finish_blocking_epics_and_memory.md).

The two hold dependencies are **now closed**, but [`sase-xe.16`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-xe/sase-xe.16.md) and [`sase-133`](https://github.com/sase-org/sase--beads/blob/main/pages/sase-133/README.md) remain open. [`.5`'s backlog audit](https://github.com/sase-org/sase--beads/blob/main/pages/sase-1ae/sase-1ae.5.md) depends on `.4`. Next: finish `sase-1aq`'s dispatch/parity landing, publish and verify the two memory updates, then run `.5` and close the parent.
