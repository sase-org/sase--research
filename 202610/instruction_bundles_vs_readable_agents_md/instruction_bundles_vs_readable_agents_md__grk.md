# Instruction bundles: transparency, benefits, and whether to proceed or revert

**Researcher:** grk (independent swarm member)  
**Date:** 2026-10-14  
**Question:** After the migration from committed agent instruction files toward
memory-built instruction bundles (epic `sase-1ko` / E3), are an agent's core
instructions still inspectable? Must new users and non-SASE agents run a `sase`
command to see them? What are the immediate and long-term benefits? Should this
work continue, or should it be reverted?

**Verdict:** Do not revert E1–E3. Finish the E3 soak and install sync. Do not start
E4 (untracking the full `AGENTS.md` tree) until the human and fresh-clone path is
in place. The transparency complaint is real for *what a SASE agent received*, and
it is a preview of E4's cost for *new users*, but it is not a reason to roll the
delivery cutover back.

---

## 1. What the user is looking at

Two different migrations are easy to collapse into one:

| Stage | What it is | Status on 2026-10-14 |
| --- | --- | --- |
| **E1** `sase-1gu` | Scoreboard + Grok `--rules` stopgap + Claude helper guard | Closed 2026-10-06 |
| **E2** `sase-1h3` | Shadow-render a bundle and manifest at every root invoke; do not deliver it | Closed 2026-10-06 |
| **E3** `sase-1ko` | Deliver that bundle once through each adapter; suppress SASE-owned native files | In progress (acceptance phase `sase-1ko.10`) |
| **E4** (not started) | Stop committing full generated `AGENTS.md` / shims in the sase repo; leave a stub + `sase instructions sync` | Planned only |
| **E5** (not started) | Home files and other projects; interactive launches | Planned only |
| **E6** (optional, not started) | TUI MEMORY deck: Manifest / Ledger / Bundle cards | Planned only |

The worry — "I used to open `AGENTS.md`; now I need a `sase` command" — is the
**E4/E5 end state**, plus an **E3 inspection gap** that already exists for SASE
runs. E3 has not deleted the files. This checkout still tracks **20** generated
instruction files (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `QWEN.md`, `OPENCODE.md`
at the root and under `tools/`, `src/sase/ace/`, `demos/tapes/`).
`sase instructions list` still reports six `AGENTS.md` documents (project,
three nested custom files, home, chezmoi). `git log --since='60 days ago' -- AGENTS.md`
is still **88** commits.

So: a new user who clones the repo and runs `claude` or `codex` still gets a
committed full file. A SASE agent launched today does **not** load that file.
Those are different audiences, and E3 split them on purpose.

## 2. What a SASE agent actually receives now

Architecture (R-delivery R1/R4/R6, implemented in E2/E3):

1. Memory notes under `sase/memory/` (and home memory) remain the **source**.
2. At each `provider.invoke`, Python compiles one Markdown **bundle** plus a
   sase-core **manifest** (schema v2).
3. The adapter delivers that bundle **once** through an explicit channel and
   suppresses SASE-owned native files.
4. A trailing marker identifies the bytes:

   ```
   <!-- sase-instructions bundle=<sha256[:12]> invocation=<id> -->
   ```

Live check on this Grok run, `research.1a.grk`:

```
sase instructions show research.1a.grk -l
00  grok  ordinary  1  sase_root  explicit  grok.rules  bc648948db99  6b4280fc40a6  20238  5062  bytes match
```

The marker in this session's injected context is `bundle=bc648948db99`. The
archived file matches the manifest digest. Channel is `grok.rules`. Native-full
for Grok in the last 24h is `0`. Home is present. Foreign Grok memory v2 is off.

The committed `AGENTS.md` is a **legacy projection**, not the delivered document:

| | Committed `AGENTS.md` | Delivered bundle (`research.1a.grk`) |
| --- | ---: | ---: |
| Bytes | 18,694 | 20,238 |
| Headings | numbered (`## 1. Core Memory`, `#### 1.1.1`) | unnumbered (`## Core Memory`) |
| Home line | absent | `Home: apollo - Bryan Bugyi's Rendezvous Server` |
| Provider overlay | none | `pkg.provider.grok` (~1,080 bytes) |
| Helper contract | mixed into the same file | excluded (`overlay`) |
| Duplicate `sase.md` cores | inlined in home + project files | `superseded_input` |

`sase instructions render -s` on this project reports 27 included sections,
~5,013 estimated tokens, cache hit in ~98 ms. `common_digest` is shared across
providers; only `pkg.provider.*` differs.

**Reading `AGENTS.md` is therefore no longer a way to see what a SASE agent was
told.** That part of the worry is already true, even though the file is still
there.

## 3. Transparency: what broke, what replaced it, what is still missing

### 3.1 The old habit was already an incomplete picture

Before bundles, `AGENTS.md` was generated by `sase memory init` from memory notes
(glossary: *Agent Instruction File*). It was never hand-authored core. It also
was not what every provider loaded:

| Provider (pre-E1, verified 2026-10-05) | What it actually loaded |
| --- | --- |
| Claude (~25% of runs) | `~/CLAUDE.md` **and** `./CLAUDE.md`: contract **twice**, conflicting repo lists; plus workspace-keyed auto-memory |
| Codex (~31%) | Home + project in one block: contract **twice** |
| Muse (~29%) | Project file only; **no home layer** |
| Grok (~13%), since ~2026-09-10 | **Nothing.** Untrusted workspace; `agents_md_files: []`. Correlated miss-rate rise from ~14% of non-research roots |
| agy | Likely `GEMINI.md` + `AGENTS.md`; no home |

Adapter directives (Claude `--append-system-prompt`, Codex
`developer_instructions`, Muse/agy prefixes) lived in Python and never appeared
in `AGENTS.md`. Claude native helpers inherited the **root** contract, including
"use `/sase_final`": 13–15 helper invocations in 30 days, **2 accepted
declarations** for a parent turn.

So "just read `AGENTS.md`" was transparent only for a human standing in the
checkout. It was not a faithful record of agent context.

### 3.2 The new inspection path (already shipped)

These commands exist and work on dismissed agents:

| Command | What it answers |
| --- | --- |
| `sase instructions show NAME` | Exact bytes that invocation archived; `bytes match` vs manifest sha256 |
| `sase instructions show NAME -s` | Section table (id, layer, included/excluded reason, lifecycle, source) |
| `sase instructions show NAME -l` | Every root and helper invocation |
| `sase instructions show NAME -H` | Helper bundle |
| `sase instructions render` | What a root agent **would** get from **today's** memory (not history) |
| `sase instructions render -p` | Parity vs legacy `AGENTS.md` (exit 1 on gaps; extra provider/frame sections are additions) |
| `sase instructions verify` | What the provider's **own** session records show was loaded |
| `sase instructions readout` | Handoff-aware declaration misses × delivery mode |
| `sase instructions list` | Still lists on-disk `AGENTS.md` files and shims |
| `sase doctor -D -C instructions` | delivery / conformance / helpers / coverage |

On-disk: `<artifacts>/instructions/NN-<provider>.md` plus `.json`, and a
content-addressed copy under `~/.sase/instructions/bundles/<sha[:2]>/<sha>.md`.
`sase agent show NAME` prints the artifacts dir. Docs:
`docs/instruction_bundles.md` ("Inspecting your instructions") and
`docs/agent_providers.md` ("Verifying instruction delivery").

That is a **more precise** transparency path than `cat AGENTS.md`, if you know
it exists.

### 3.3 The remaining gap (this is the real complaint)

1. **Casual path is gone for SASE runs.** Opening the file in the editor,
   GitHub, or a diff no longer equals "what this agent saw."
2. **The TUI still does not open the bundle.** E3 readiness research recorded
   that the Agents-tab MEMORY lane still shows `AGENTS.md as launched` (disk
   snapshot), the Files deck does not list `instructions/*.md`, and the MEMORY
   deck (Manifest / Ledger / Bundle) is **E6**, which has not started.
   `sase instructions show` was pulled into E3 as the CLI substitute.
3. **Glossary is stale.** `glossary:Agent Instruction File` still says `sase
   init` writes byte-identical `AGENTS.md` / `CLAUDE.md` / … and that those
   files are what agent CLIs read. Bundle / manifest terms are E4.5 work.
4. **`docs/instruction_bundles.md` is slightly behind the code.** It still
   says Claude and Codex "remain on legacy delivery pending their adapter
   phases." Codex is already `explicit` on this host; Claude is mixed because
   the installed host binary is behind the workspace (E3 acceptance: launch
   probes pending install sync).
5. **E4 would make the user's second fear true.** After untracking full files,
   a fresh clone without SASE installed would see only a planned **export stub**
   (≤80 lines, bootstrap clause, no `/sase_final`). Getting a full interactive
   projection would require `just agent-instructions` / `sase instructions sync`
   / `uvx --from 'sase>=X' sase instructions sync`. Those commands **do not
   exist yet**. There is no `export` or `sync` subcommand today.

The honest sentence for new users **today**: they do **not** need a `sase`
command; the files are still committed. The honest sentence for **SASE agents
today**: a human who wants the truth must run `sase instructions show` (or open
the artifacts file). The honest sentence for **the intended end state**: yes,
non-SASE sessions get a stub plus an optional generated projection; SASE
sessions get a per-invocation bundle.

## 4. Immediate benefits (already paid for by E1–E3)

These are live, or proven in harness probes on 2026-10-14, not roadmap claims.

### 4.1 Delivery correctness

1. **Grok receives the project contract and the single-turn directive.** Before
   E1 it received neither in SASE workspaces. E1 put directive + `AGENTS.md`
   on `--rules`. E3 puts the **full root bundle** (including home) on `--rules`.
   This run: `explicit` / `grok.rules` / contract 1× / home ✓ / native-full 0.
2. **Exactly-once contract.** Claude and Codex no longer get home+project
   copies of "SASE Final Declaration" (about 790 duplicate tokens, plus
   disagreeing repo lists). Harness, flag on: Claude, Codex, Grok each
   `bundle 1` / `contract 1 explicit` / `native-full 0`.
3. **Home layer for Grok (and Muse, once live observers are unblocked).** Home
   refs (Obsidian, tailnet) are in this Grok bundle. Muse historically missed
   home because of `--no-foreign-personal-context`; E3 prefix delivery is the
   fix. Live Muse observers are 429-blocked until 2026-10-19; argv still proves
   the explicit slot and dropped `--trust-workspace`.
4. **Native SASE files suppressed in SASE runs**, without suppressing
   repo-owned nested files or a foreign repo's own `AGENTS.md`. Claude uses
   exact-path `claudeMdExcludes`; Codex uses `project_doc_max_bytes=0` only in
   SASE-managed projects. Linked-repo `CLAUDE.md` still loads on read.
5. **Foreign provider memory off in SASE runs.** Claude auto-memory was
   workspace-keyed and invisible to review (this program previously loaded
   another workspace's 15-note index). Grok memory v2 is disabled. That is the
   `foreign_memory = yes` decision on `sase-1ko`.
6. **Claude instructions moved into the system prompt**
   (`--append-system-prompt-file`) instead of a user-message attachment that
   compaction re-reads from disk.

### 4.2 Helper safety (two-slot delivery, R10/R11/R14)

7. **Root and helper are different documents.** Helper overlay carries
   `pkg.helper.contract`; root overlay carries `pkg.root.final_declaration` and
   `pkg.provider.*`. They do not mix.
8. **Helpers cannot close the parent's turn.** E1 already dropped helper
   `sase final` attempts to 0. E3 helper probe: general-purpose attempted once
   and was **denied**; Explore refused from the helper bundle without a tool
   call; neither transcript contained the root bundle id.
9. **Codex children inherit the root slot honestly** (`inherits_root`) instead
   of silently picking up a native `AGENTS.md` the parent had suppressed.

### 4.3 Observability and operations

10. **Provenance.** Every invocation has bytes, sha256, `common_digest`,
    section table, facts, channel, CLI version, session ids, and
    included/excluded reasons. `bytes match` is a one-command integrity check.
11. **Scoreboard that reads the provider's records**, not SASE's disk snapshot.
    Pre-migration `capture_instruction_snapshot` would have claimed Grok saw
    `AGENTS.md` while `agents_md_files` was empty.
12. **Handoff-aware readout.** Naive "has `final_submission.json`" made Codex
    look like ~38% noncompliant; those were monitor handoffs. Real Grok misses
    fell from **14% → 5%** after E1 (handoff-aware, Sep 10–Oct 5 vs Oct 6–13).
13. **Per-provider sunset kill switches**, default on:
    `claude_explicit_instructions`, `codex_explicit_instructions`,
    `grok_explicit_instructions`, `muse_explicit_instructions`. One
    `sase flag disable <key>` per execution host restores that provider's E1
    after-state. Flag-off harness rows reproduce 2× native Claude/Codex
    contracts.
14. **Atomic per-invocation fallback.** Render failure, invalid bundle,
    oversize, or adapter materialization restores native discovery for **that
    call**, notifies once per host/provider/reason/day, and never launches with
    an empty instruction context.
15. **Codex shadow-home hygiene (`sase-11s`).** Allowlist copy instead of
    symlinking sqlite/`sessions`/`memories` from the real `~/.codex`.
16. **Warm render is cheap.** This preview: cache hit 98.5 ms. E3 acceptance:
    Muse ordinary warm p95 142.7 ms; declaration-recovery 241.3 ms (under the
    250 ms ordinary budget; recovery is the known small-n outlier).
17. **Parity still ties the bundle to memory content.** `render -p` in sase,
    bob-cli, actstat, and job passed in the acceptance record; extra sections
    are `frame.*` and `pkg.provider.*`, not missing cores. `git status` was
    unchanged.
18. **`common_digest` makes cross-provider sameness checkable.** A research
    swarm can prove members differed only in the provider overlay.

### 4.4 Behavioral signal already in the wild

19. **Grok compliance recovered under a handoff-aware metric** after the E1
    stopgap (14% → 5% misses). That is the strongest existing evidence that
    instruction delivery changes agent behavior, not just logs.
20. **Muse memory-read rate is the E3 watch metric.** Oct 7–13: Muse 0.57
    audited reads/run (35% of runs) vs Grok 1.87 (93%). Muse is the provider
    that lacked the home layer; if explicit prefix delivery works, this number
    should move.

## 5. Long-term benefits (E4–E7; not yet delivered)

These are why the program continues past "delivery works." They are **conditional
on not reverting**, and several of them are also the answer to the transparency
worry if sequenced correctly.

### 5.1 Stop generating a lie into git (E4)

21. **Instruction-file churn goes to ~0.** 88–112 commits / 60 days currently
    touch `AGENTS.md` because every memory edit regenerates it. After E4,
    editing a reference note changes the **next bundle** and no tracked file.
22. **Twenty generated files collapse to two** in the sase repo: a budgeted
    `mode: export` stub `AGENTS.md` (≤80 lines, bootstrap clause, **no** turn
    obligations) plus a two-line `CLAUDE.md` import. Exit check:
    `git ls-files | grep -cE '(^|/)(AGENTS|CLAUDE|GEMINI|QWEN|OPENCODE)\.md$'`
    prints `2`.
23. **CI catches stub drift before regeneration.** `sase instructions export
    --check` replaces the instruction half of `sase init memory --no-commit`,
    which today can mask drift by rewriting files in CI.
24. **Last-known-good store replaces "fall back to native files."** E3's
    fallback still depends on the committed full files. E4 cannot delete those
    files until LKG exists; the E3 acceptance notes already flag this as an E4
    prerequisite.
25. **Nested `tools/` / `ace/` / `demos/tapes/` copies become path-scoped
    reference notes** instead of five-file shim sets. Duplicate Symvision text
    merges.
26. **agy (and Muse if still legacy) switch in the same change**, so leftover
    native double-load disappears when the files go.

### 5.2 Fresh clones and non-SASE agents (E4, R12/R13)

27. **A clone without SASE installed still works**, and it is **more honest
    than today.** Today's committed `AGENTS.md` tells an interactive `claude`
    in a fresh clone to use `/sase_final`, stay inside `sase_<N>` workspaces,
    and read sidecars that were never cloned. The stub is written for that
    reader: build/test guidance + "if your context lacks generated
    instructions, run `just agent-instructions` (or `uvx … sase instructions
    sync`), then **read** the file it printed."
28. **`sase instructions sync` is the mechanical path** for Claude (`@import`
    of a gitignored generated file) and Codex (`AGENTS.override.md` replacing
    `AGENTS.md`). It is hermetic, refuses workspaces, will not overwrite
    user-owned files, and keeps `git status` clean.
29. **Generating during a session is specified correctly.** A file created
    mid-turn is not loaded natively for the rest of that turn; the clause says
    generate **then read**. That is the researched answer to "can't they just
    run a sase command?"

### 5.3 Home, fleet, and interactive sessions (E5, R14)

30. **`~/AGENTS.md` / `~/CLAUDE.md` stop carrying the SASE Final Declaration
    into every interactive session under `$HOME`.** That is a present bug:
    home files are a chezmoi render of home memory and include the turn
    contract.
31. **bob-cli and actstat** pick up export+sync through `sase init` instead of
    their own five-file sets (inventory: 35 generated files across four
    places).
32. **`sase tmux-agent`** (raw CLI in a tree) goes through the delivery hook
    with `mode: interactive`, so interactive launches are not a second,
    unmeasured path.

### 5.4 Seeing instructions in the product (E6)

33. **Identity-header chip:** quiet when delivery is 1×, loud on `‼2×` or `∅`.
34. **MEMORY deck** with Manifest, Ledger, and Bundle cards: exact bytes, which
    notes were inlined / offered / read / withheld / foreign, pinned to the
    blob the agent saw.
35. **Clan/tribe audience strip:** one `common_digest` shared by a swarm.
36. **Memory pane "Seen by":** editing a core note shows how many runs inline
    it.
37. **CLI/TUI agreement** via a Rust `ledger_view`. This is the restoration of
    casual transparency **inside SASE**, which is the user's actual daily
    surface.

E6 can run **alongside** E4. It does not need files to be deleted first. If the
pain is "I can't see what the agent got," E6 (or even wiring the existing
bundle files into the Files deck / MEMORY lane) is the cheaper fix than
reverting delivery.

### 5.5 Audiences and budgets (E7, conditional)

38. **`when:` on notes**, evaluated from host-known launch facts (provider,
    actor, purpose, host, vcs, …), not `%tag`.
39. **Hard rules and baseline triggers stay unconditional (R9).** A researcher
    audience cannot drop `/sase_final` or the read triggers.
40. **Per-audience budgets** ratcheted from the E2 baseline
    (`instructions_budget_baseline.json` already attached to `sase-1h3`).
41. **Optional `SASE.md` composition spec** only if a project needs layout that
    notes cannot express (`corpus-before-mechanism`).

E7 is gated on measured value from E2/E3 manifests joined to `memory_reads.jsonl`.
It is not a reason to revert, and it is not required to keep E3.

## 6. What reverting would undo

A full revert of E3 (flags off everywhere, then delete the adapter work) returns
each provider to E1's after-state:

| Provider | After revert (E1) | After E3 explicit |
| --- | --- | --- |
| Claude | contract 2× native (`~/CLAUDE.md` + `./CLAUDE.md`), auto-memory on | 1× system-prompt bundle, auto-memory off |
| Codex | contract 2× native, sqlite-linked shadow home | 1× `developer_instructions`, allowlist home, `project_doc_max_bytes=0` |
| Grok | `--rules` = directive + project `AGENTS.md` only; **no home** | full bundle including home |
| Muse | `--trust-workspace`, no home | prompt prefix, no trust flag (once quota allows observers) |
| Helpers | E1 static template + PreToolUse guard (if E1 kept) | helper bundle id, no root id |

Reverting **E1 as well** puts Grok back to loading **zero** files.

Costs that do not show up in a git revert:

- The scoreboard, manifests, `show`/`render`/`verify`/`readout`, and doctor
  group become a museum of a delivery path you no longer use — or they have to
  be torn out too.
- Sunset flags are the designed rollback. They are cheaper than a code revert
  and already proven in harness flag-off rows.
- After E4, flags **cannot** roll back: native files would be the stub. That is
  why E4's entry gate is "E3 sunset flags **removed**" and LKG exists.

A **partial** revert (keep E1+E2, disable E3 flags) restores `cat AGENTS.md` as
an approximation of Claude/Codex/Muse native loads, and keeps the scoreboard.
It also restores the duplicate contract, Grok-without-home, Muse-without-home,
and auto-memory. It does **not** restore a faithful picture: Grok would still
get `--rules` rather than the file, helpers would still differ, and Python
directives would still be invisible.

## 7. Risks of proceeding (without reverting)

These are reasons to **sequence**, not to undo.

1. **Install skew.** Host `sase` at E3 acceptance was `8847d07a08` (Grok/Muse
   explicit, no Claude flag). Live 24h scoreboard on this host still shows
   Claude `legacy:provider_legacy` / contract 2× / auto-memory, and Muse
   `shadow` / home ✗. Codex and Grok are `explicit` / 1×. Do not read that mix
   as "bundles failed"; it is "not every binary on every host has every adapter
   yet."
2. **Doctor WARN noise.** `instructions.conformance` currently WARNs because
   this running Grok session's invocation id collides with other workspace Grok
   sessions (root marker 0× / 2×). Independent harness observers scored 1×.
   Soak metrics need the same care the readout already learned for monitor
   handoffs.
3. **Muse live proof is incomplete** until 2026-10-19 quota reset.
4. **Claude 2.1.296+ `instructionFiles` falls back to `AGENTS.md` once
   `CLAUDE.md` shims are deleted.** E4 must account for that or Claude native
   sessions load the stub as `AGENTS.md` (acceptable) or a leftover full file
   (not). E3 already excludes exact SASE-owned paths.
5. **Deleting files before LKG + export/sync strands new users** and removes
   E3's native fallback. That is the one revert-like disaster in the remaining
   roadmap.
6. **Self-hosting / public-repo readers.** `sase-org/sase` is public.
   Contributors who never install SASE need the stub to be good. That work is
   E4.1, not E3.

## 8. Recommendation

### Proceed with E3. Do not revert.

The delivery bugs were measured, the cutover is reversible per provider with
one flag, and this Grok session is itself a working explicit bundle
(`bc648948db99`, `bytes match`). Reverting would buy a familiar filename and
re-open Grok-empty, contract-twice, helper-final, and auto-memory.

### Hold E4 until three things exist

E4 is where "new users need a `sase` command" becomes true. It should not start
because E3 landed. Entry from the epic definition is already strict (flags
removed, every host on E3). Add, as a product gate:

1. **`sase instructions export` stub + `sase instructions sync`** (or
   `just agent-instructions`) implemented and documented as the human path.
2. **Glossary + docs** updated so `AGENTS.md` is described as a projection /
   stub, and `sase instructions show` is the answer to "what did this agent
   get?"
3. **A SASE-native view of the bundle** — E6, or a thinner slice: register
   `instructions/*.md` as artifact files and point the MEMORY lane at
   `sase instructions show` instead of `AGENTS.md as launched`.

Until then, keep committing the full files. They are the E3 fallback, the
fresh-clone story, and the user's current reading habit. They are also the
wrong document for SASE agents; that is acceptable for a soak.

### Optional: pull transparency forward without touching delivery

If the pain is daily inspection, do **not** revert adapters. Do the cheap
visibility work:

```bash
sase instructions show <agent>          # exact bytes
sase instructions show <agent> -s       # sections
sase instructions render | less         # what the next agent would get
sase instructions verify -a <agent>     # what the CLI actually loaded
```

Put those four lines in the Agents-tab empty/help text. That closes most of the
"no longer transparent" gap **this week**, without E4's bootstrap risk.

### How to actually roll back if soak fails

Do not `git revert` E3. On each execution host:

```bash
sase flag disable claude_explicit_instructions   # and/or codex, grok, muse
sase instructions verify --since 24h
```

If a single provider's explicit-run misses rise more than a couple of points
above the attached E3 baseline, disable **that** provider. The other three stay
on bundles. That is what the sunset flags are for.

## 9. Direct answers

**Are an agent's core instructions no longer transparent?**  
They are no longer in the committed `AGENTS.md` for SASE runs. They **are**
transparent as archived bytes (`sase instructions show`, artifacts
`instructions/NN-*.md`, content store). They are **not** transparent in the
TUI yet. Source of truth is still `sase/memory/**`, which was always the case.

**Must new users / non-SASE agents generate files with a `sase` command?**  
**Not today.** The 20 files are still tracked. **Yes in the E4 design**, via a
committed stub that tells them to run `just agent-instructions` / `sase
instructions sync` and then read the result. That command is not implemented.
Do not untrack files until it is.

**Should we proceed or revert?**  
Proceed with E3 soak and install sync. Revert only a provider whose soak
misses. Hold E4/E5 until export, sync, docs, and some in-product bundle view
exist. Treat E6 as the transparency epic, not as optional polish.
